## GitHubとSitesの関係

このコピーは共有・開発用。既存Sitesのソースリポジトリを置き換えたり、GitHubからの自動公開を有効にしたりするものではない。GitHubの変更が公開サイトに自動反映されるとは想定しないこと。

公開作業は以下の順で行う。

1. 既存Sitesの最新バージョンとソースを取得する。GitHub側と元のコミットを比較する。
2. 競合や他の作業者の変更を確認して、公開対象の変更を統合する。古いスナップショットで丸ごと上書きしない。
3. 対象の回帰テストと `npm test`、必要なブラウザ確認を行う。
4. `npm run build` で `dist/server/index.js` を生成する。
5. 既存Sitesのソースへ正確な内容をコミット・プッシュし、そのコミットから公開用アーカイブを作成する。
6. 同じproject_idへバージョン保存・デプロイする。公開範囲・認証・URL・SAVESを維持する。
7. 公開結果のバージョンとコミットを確認し、GitHub側にも実際に公開した変更を反映する。

GitHub Actionsはテストとビルドだけを実行する。公開トークンを必要とするデプロイ処理は設定していない。

## セーブについて

- ローカルの `dist/` を起動しても本番R2の中身は得られない。
- `SAVES` という名前だけでは本番データへアクセスできない。
- 公開環境が供給する認証済みユーザー識別子を使い、アカウントごとのR2キーを生成する。
- ローカルストレージはオリジンごとに分かれる。URL変更で端末内セーブが見えなくなる問題を再発させないため、既存URLを維持する。
- 読取り・書込みAPIのアカウント分離、Origin確認、競合検出、サイズ上限を維持する。
- 別ホスティングへ移行する場合は認証境界・R2接続・保存先移行を別途設計する。GitHub Pagesへ置くだけではクラウド保存は動かない。
